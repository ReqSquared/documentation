We've seen this every week. Reqs piling up. Recruiters running between meetings. Some chairs empty. Some chairs buried.

Standard ATS reporting shows you the counts. Number of reqs per recruiter. Average per team. Distribution by region. Useful for executive summaries. Insufficient for the actual decision: _which req should move, to which recruiter, right now_.

The **Load Balancing BlueCube** approaches this differently. Instead of treating requisitions as isolated rows in a report, the cube analyzes historical recruiting behavior to discover operational patterns, applicant tendencies, and recruiting workload personas that emerge across the recruiting lifecycle.

Inside the cube are models. Some are simple statistical models. Some are machine learning models. Each model is another analytical lens used to measure, compare, classify, and explain recruiter workload behavior from a different perspective.

## Cube #2: Load Balancing
